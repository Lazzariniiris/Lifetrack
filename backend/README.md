# LifeTrack API

FastAPI service for optional meal-image analysis. Android authenticates directly with Supabase Auth and sends its access token to this API; the API does not proxy registration or login. Images require explicit consent, are validated in memory, sent to OpenAI, and discarded after analysis.

## Local setup

Python 3.12 and `uv` are required.

```powershell
Copy-Item .env.example .env
uv sync --group dev
uv run uvicorn app.main:app --reload
```

Fill `.env` with development credentials only. `SUPABASE_ANON_KEY` is used together with each user's JWT so PostgreSQL RLS remains active. No service-role key is required or accepted by the application.

## Database migrations

Apply the numbered migrations in order:

1. `sql/001_initial.sql`: base tables, ownership RLS, triggers, and signup profiles.
2. `sql/002_extended_nutrition.sql`: fiber, sugar, and sodium values.
3. `sql/003_production_hardening.sql`: health profiles, habit-log owner integrity, pending/completed meal records, distributed daily quotas, and the private `meal-images` bucket with per-user Storage RLS.

All three files are idempotent and `003` includes compatibility conversion for meal rows created by `001` and `002`. Apply them through the Supabase SQL Editor, Supabase CLI, or the helper below. The helper requires a Supabase management access token, only while running migrations; this token is not an API runtime variable.

```powershell
$env:SUPABASE_URL = "https://your-project.supabase.co"
$env:SUPABASE_ACCESS_TOKEN = "your-management-token"
uv run python scripts/apply_migrations.py
```

The private bucket expects object names in `<user-uuid>/<filename>` form. The current analysis endpoint does not persist uploaded image bytes. `photo_path` only records an already-owned private object path.

## API contract

- `POST /v1/meals/analyze`: authenticated multipart upload with `consent=true`; accepts JPEG, PNG, or WebP up to `MAX_IMAGE_BYTES`.
- `POST /v1/meals`: saves a structured analysis using the client-provided UUID `id`; repeating the UUID returns the original owned row.
- `GET /v1/meals?limit=20&offset=0`: lists owned meals with exact pagination metadata.
- `PATCH /v1/meals/{id}`: applies owned corrections and marks analytical changes as `corrected`.
- `DELETE /v1/meals/{id}`: deletes an owned meal and its private image when present.
- `GET /health/live`: process liveness only.
- `GET /health/ready`: verifies Supabase/PostgREST reachability and configuration without calling or billing OpenAI.

Structured models reject unknown fields. Confidence is numeric from `0` to `1`; food portions include `estimated_grams`, alternatives, and observations. The nutrition disclaimer is injected by the server and is not generated by OpenAI or accepted in save requests.

`DAILY_ANALYSIS_LIMIT` controls the per-user daily OpenAI quota enforced transactionally in PostgreSQL. HTTP 429 is returned before calling OpenAI when the quota is exhausted.

Errors use a stable envelope and return the correlation ID in both the body and `X-Request-ID`:

```json
{"error":{"code":"IMAGE_TYPE_UNSUPPORTED","message":"Use a JPEG, PNG, or WebP image.","request_id":"..."}}
```

## Railway

Deploy from `backend/` with `railway.toml` after applying `001`, `002`, and `003`. Configure only the runtime values in `.env.example`. Railway supplies HTTPS; OpenAPI is available at `/docs`. Set `CORS_ORIGINS` to a comma-separated allowlist when browser clients are used. Native Android requests do not require CORS.
